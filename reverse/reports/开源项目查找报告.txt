二、最值得用于继续逆向的项目

1. JackJiang2011/MobileIMSDK —— 通信实现来源线索，强关联
https://github.com/JackJiang2011/MobileIMSDK

APK 的 types=1/2/3/4/50/51/52/54 与官方协议中的心跳、业务数据、退出、ACK、登录响应、心跳响应、错误和被踢消息对应。
APK 内 QoS4SendDaemon 风格的重传日志、QoS发送/接收守护、心跳守护、自动重登录及ClientCoreSDK模块也有源码级对应。
APK 本地 Rust 模块名：qos4_send_daemon.rs、qos4_receive_daemon.rs、keep_alive_daemon.rs、auto_re_login_daemon.rs、client_core_sdk.rs。
这是强关联的移植/改造线索；尚不能绑定具体公开 Rust 仓库、作者或提交。

关键差异：官方登录类型为0，本 APK 使用6；官方有毫秒计时实现，本 APK 已还原的 Rust 逻辑按秒判断。
APK 已确认的默认值：心跳30秒、检测2秒、超时35秒、自动重登录3秒；QoS扫描60秒、重发年龄阈值3001秒、最多2次成功重发。
这些 APK 值来自原始二进制；不能用官方当前默认值覆盖，也不能据此假定官方服务端可直接替换本 APP 服务端。
官方树内的 Flutter 社区版是 Dart TCP 学习参考实现，本轮读取的官方树未包含 Rust 源文件。
官方仓库的开源范围与付费精编版本范围不同，具体源码文件和许可见 network_candidates.json。

2. fzyzcjy/flutter_rust_bridge —— 已确认的桥接依赖
https://github.com/fzyzcjy/flutter_rust_bridge

原始 Rust ELF 的 Cargo 构建路径明确记录 flutter_rust_bridge-2.0.0-dev.37。
此前已还原 Rust事件→FRB生成层→Dart事件分发的交叉调用；该项目可帮助解释生成桥接代码与运行时。
库名/版本与原始字符串已逐字节核对。具体 Dart/Rust 业务文件不属于上游桥接库。

3. jerson/rsa-mobile 与 jerson/flutter-rsa —— APK 内 RSA 组件来源
https://github.com/jerson/rsa-mobile
https://github.com/jerson/flutter-rsa

librsa_bridge.so 的 Go build info 明确依赖 github.com/jerson/rsa-mobile，版本标为(devel)，无法恢复具体提交。
原库有对应包路径、桥接实例/操作函数和34项RSA操作；Flutter AOT另有 package:fast_rsa 命名空间。
这能确认组件来源，但不意味着该组件的全部功能均被业务调用。
当前已还原的服务器配置 RSA 解密路径走 Dart encrypt/PointyCastle；Go RSA 在包内不等于该登录路径调用 Go RSA。

4. Tokio / tokio-tungstenite / tungstenite —— 已确认的 Rust 网络依赖
https://github.com/tokio-rs/tokio
https://github.com/snapview/tokio-tungstenite
https://github.com/snapview/tungstenite-rs

原始 Cargo 构建路径记录：tokio 1.40.0；tokio-tungstenite 0.21.0；tungstenite 0.21.0。
这些仓库用于解释异步任务和 WebSocket 收发基础设施；APP 的 types/msg_type/心跳业务规则由自定义层决定。
其它本地版本包括 chrono 0.4.38、uuid 1.10.0、serde_json 1.0.128。
共提取35个库名/版本对、155条路径证据，均按原ELF文件偏移核对；这是部分版本库存，不能替代完整 Cargo.lock。
